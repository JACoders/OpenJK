## Working practices (owner's requests, keep them)

- Language: answers to the owner in French, short; everything persisted (docs, comments, commits) in English, full sentences. Never mention the earlier proof-of-concept code base.
- The owner commits, never Claude: give a Conventional Commits title with the step first, for example `feat(netcodec): step 6, ...`; do not stage files. If a commit is ever made here, signing needs `git -c gpg.program=C:/Logiciels/GnuPG/bin/gpg.exe commit ...` (the key is in Gpg4win; Git Bash's own `gpg` has none; the passphrase prompt opens in a window).
- C++: C++20 inside netcodec, C++ Core Guidelines (named casts, `noexcept`, `[[nodiscard]]`, `constexpr`, `std::span`, RAII, initialised members), unsigned arithmetic for bit manipulation; strict warnings as errors (top-level project); clang-tidy at zero (`mingw-clang-tidy` preset); no exceptions. Comments describe the format and the code, never the Python prototype.
- Every change: build and run the golden tests on several presets (Release, Debug with index checks, x86, ASan + UBSan), then the benchmarks; a cleanup must show no performance regression. Compare timings with the legacy timings of the same run (this machine varies by up to 8 % between runs). Changes of a few percent are only visible in the warm timing (fastest of 5 codings per message) of step 6 part C, A/B against a build of the previous commit; the cold benchmark is memory-bound and varies by up to 9 %, more while the owner plays.
- GCC is built and timed only on the Debian VM, never on the Windows machine (a portable GCC there was too slow, the owner stopped it, and it does not reproduce the Linux timings); this machine builds with llvm-mingw clang only.
- GCC-only warnings exist (`-Wuseless-cast` on 32 / 64-bit size types: use `ToU32`); MSVC is stricter on old engine code (the legacy benchmark is built in C++11 without the project settings).
- Mod compatibility is never a criterion and never a question to ask; no loss of precision; as few settings as possible.
- Timing (7 November 2026): GCC on Linux is the server target (about 95 % of servers) and has more weight than MSVC for encoder changes; every encoder or decoder change gets an alternated A/B against the previous commit with clang here (`codemp/netcodec/scripts/ab_clang.sh`, only while the machine is quiet: ask the owner) and with GCC 12 on the Debian VM (`codemp/netcodec/scripts/ab_gcc.sh`, aligned code); MSVC with `codemp\netcodec\scripts\ab_msvc.bat` when it matters (if the VM has no git, run `bash codemp/netcodec/scripts/ab_msvc_ref.sh` here first; the script refuses a stale reference); GCC 16.2 (`ab_gcc_podman.sh`) in the final measurements. Tools and profiler: [step-06-cpp-codec.md](step-06-cpp-codec.md), part C, "Timing and profiling tools".
- The VM logs are in the shared folder (`build-netcodec/validate-linux.log`, `validate-windows.log`): read them directly; the owner only pastes the summary. A validation run during which a netcodec source changed now ends with a FAIL line (it tested a mix); the A/B summaries warn when the machine was busy (legacy coder moving by more than 4 %): then run again.
- Test hashes: `netcodec_ROUNDTRIP_HASH` and `netcodec_SYNTHETIC_HASH` in `test/CMakeLists.txt` change with the format, the tables or the generator (update them from clang Release, then every preset and both VMs must agree); `angle_hash.py` gives the determinism test's constant.
- Patching files from scripts: write the Python script with the Write tool and run it with `python -I` (Git Bash heredocs mangle `\n` and backslashes); bytes written with `write_bytes(s.encode())` keep LF (and CRLF for `.bat`, which must stay CRLF).

## Known issues found on the way (not fixed)

- Legacy client (`CL_ParseSnapshot`, `codemp/client/cl_parse.cpp`): when the old snapshot had no vehicle, the server deltas the vehicle player state from nothing (`MSG_WriteDeltaPlayerstate(msg, NULL, &frame->vps, qtrue)`) but the client deltas it from `old->vps`. Seen while writing the legacy benchmark; not tested (the benchmark follows the server and the client as written and found no failure on the recordings).


- The `user*` mod fields are networked 1 bit wide, floats included: only the lowest bit reaches the client unless a mod widens them with the overrides files ([../02-engine-code-findings.md](../02-engine-code-findings.md) section 2.2).

- With `sv_ratePolicy 2` and `sv_maxRate 0`, the client rate becomes 0 and `SV_RateMsec` divides by zero (`codemp/server/sv_client.cpp:1090`, `codemp/server/sv_snapshot.cpp:679`). Read only, not tested.
