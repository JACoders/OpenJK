# P6-03: Finalize Operator and Player Documentation

## Objective

Document the actual validated split-screen workflows and operational limits.

## Primary ownership

User, server-operator, contributor, troubleshooting, and release-note documents.
Do not edit production code, packaging, or release manifests.

## Work

1. Document local party setup, device assignment, profiles, controls, consoles,
   virtual keyboards, hosting, internet joining, and remote fifth players.
2. Document vanilla compatibility, capacity rules, ports, passwords, and failure
   recovery for server operators.
3. Document architecture boundaries, test harnesses, and screenshot review.
4. State verified limitations explicitly; omit untested claims.

## Acceptance criteria

- Every instruction is replayed successfully against the Phase 5 candidate.
- Screenshots come from the shipped game and use paths without spaces.
- Troubleshooting maps symptoms to logs, telemetry, and corrective actions.
- Draft release notes distinguish completed behavior from known limitations.
