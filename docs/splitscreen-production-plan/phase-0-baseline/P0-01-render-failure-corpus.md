# P0-01: Capture Rendering Failure Corpus

## Objective

Create canonical in-game captures of every currently broken layout and state.

## Primary ownership

`tests/splitscreen/cfg` capture scenarios and `/tmp/openjk-splitscreen-baseline`
artifacts. Do not edit engine, cgame, UI, or renderer source.

## Work

1. Capture settled 2-, 3-, and 4-player FFA frames before and after distinct
   movement for every player.
2. Capture death, respawn, spectator, top menu, profile, saber, Force, console,
   virtual keyboard, scoreboard, and map-change frames.
3. Seed visibly distinct names, models, saber colors, locations, view angles,
   health, armor, scores, and teams.
4. Record the exact build, CVARs, commands, timestamps, and expected owner of
   each viewport.
5. Label duplicated cameras, black regions, wrong HUD identities, clipping, and
   stale state in a manifest.

## Acceptance criteria

- Every capture is generated by `screenshot_png` and visually inspected.
- The known four-player duplicated-camera/black-region defect is represented.
- Scenarios are deterministic enough to reproduce within documented tolerances.
- No test claims success solely because clients connected.
